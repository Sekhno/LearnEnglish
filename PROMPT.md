### Правило, которое легко запомнить

|              | Рядом | Далеко |
| ------------ | ----- | ------ |
| Один предмет | This  | That   |
| Несколько    | These | Those  |

Обрати внимание

С `this` и `that` обычно используется is, а с `these` и `those` — are, когда эти слова выступают подлежащим с глаголом to be.

Проверь себя

Перед тобой лежат несколько ключей. Как сказать «Это мои ключи»?

This is my keys.

These are my keys.

Those are my keys.

Правильно! Ключей несколько, и они рядом.

Ниже промпт, рассчитанный на существующий проект. Он просит Claude изучить архитектуру, изменить отображение и при необходимости структуру данных, сохранив текущие уроки.

# Задача: переработать отображение теоретического материала в приложении для изучения языков

## Контекст

В приложении для изучения иностранных языков уже реализованы уроки с теоретической и практической частями.

Сейчас теоретический материал отображается слишком примитивно: длинной строкой текста, иногда с Markdown-разметкой, таблицами и списками. Это неудобно для чтения, особенно при изучении грамматики.

Необходимо превратить теоретическую часть в полноценный, визуально привлекательный, структурированный и интерактивный учебный материал.

## 1. Анализ существующего проекта

Перед реализацией:

- Изучи текущую архитектуру Angular-приложения.
- Найди компоненты, отвечающие за отображение теории.
- Определи формат хранения уроков и теоретического контента.
- Проверь, как сейчас обрабатывается Markdown.
- Изучи существующую интеграцию с Piper TTS.
- Используй существующие UI-компоненты, стили и подходы проекта.

Не создавай параллельную систему, если существующую можно расширить.

## 2. Улучшение визуального представления

Каждый теоретический урок должен поддерживать следующие элементы:

### Заголовок и введение

- Название грамматической темы.
- Краткое описание того, чему научится пользователь.
- Уровень языка (A1–C2), если он указан.
- Понятное объяснение, зачем используется рассматриваемая конструкция.

### Теоретические блоки

- Подзаголовки и небольшие абзацы.
- Выделение важных правил.
- Списки.
- Корректно оформленные таблицы.
- Информационные блоки с подсказками.
- Предупреждения о типичных ошибках.
- Примеры правильного и неправильного употребления.
- Сравнительные блоки для похожих конструкций.

### Визуализация

Реализуй переиспользуемые компоненты:

- GrammarRuleCard — карточка грамматического правила.
- ExampleCard — пример с переводом и озвучиванием.
- ComparisonTable — сравнительная таблица.
- VocabularyCard — слово с переводом и произношением.
- GrammarTip — полезная подсказка.
- CommonMistake — распространённая ошибка.
- VisualExample — иллюстрация с подписью.
- MiniQuiz — небольшой интерактивный вопрос внутри теории.

Используй адаптивный дизайн. На мобильных устройствах карточки должны удобно располагаться вертикально.

Не перегружай интерфейс цветами. Сделай дизайн современным, спокойным и ориентированным на обучение.

## 3. Интеграция Piper TTS

Добавь возможность воспроизводить:

- Отдельные иностранные слова.
- Фразы.
- Предложения из примеров.
- При необходимости — целый учебный абзац.

Требования:

- Кнопка воспроизведения рядом с текстом.
- Визуальное состояние загрузки и воспроизведения.
- Защита от одновременного запуска нескольких аудиозаписей.
- Повторное воспроизведение.
- Использование существующего сервиса Piper TTS.
- Учёт выбранного языка и доступной голосовой модели.
- Корректная обработка ошибок.
- Возможность повторного использования полученного аудио через кэш, если это соответствует существующей архитектуре.

Не пытайся озвучивать Markdown-синтаксис.

## 4. Структурированный формат теоретического материала

Изучи целесообразность перехода от единого Markdown-текста к структурированной модели данных.

Предпочтительно использовать типизированную структуру блоков, например:

- paragraph
- heading
- grammarRule
- example
- comparison
- vocabulary
- tip
- warning
- image
- miniQuiz

Каждый блок должен содержать данные, необходимые для его отображения.

Контент должен храниться отдельно от компонентов Angular.

Если существующий формат Markdown уже используется во многих уроках, обеспечь обратную совместимость. Не допускай потери существующих данных.

Не выполняй массовую миграцию без проверки корректности преобразования.

## 5. Улучшение учебной методики

Теория должна не просто перечислять правила, а обучать.

Рекомендуемая последовательность:

1. Что изучаем и зачем.
2. Простое объяснение.
3. Визуальная иллюстрация.
4. Основное грамматическое правило.
5. Примеры с переводом и озвучиванием.
6. Сравнение похожих конструкций.
7. Типичные ошибки.
8. Краткое резюме.
9. Мини-проверка понимания.

Не все блоки обязательны для каждой темы — структура должна соответствовать содержанию урока.

Для начинающих используй короткие, понятные объяснения, без избыточной лингвистической терминологии.

## 6. Пример переработки материала

Текущая теория:

**Demonstrative pronouns**

| <br>     | Near  | Far   |
| -------- | ----- | ----- |
| Singular | this  | that  |
| Plural   | these | those |

- This is my pen.
- That is your car.
- These are my keys.
- Those mountains are beautiful.

Ожидаемый результат:

Полноценный урок «Demonstrative Pronouns»:

- Объяснение указательных слов.
- Различие между близкими и удалёнными предметами.
- Различие единственного и множественного числа.
- Четыре визуальные карточки THIS / THAT / THESE / THOSE.
- Таблица сравнения.
- Примеры с переводом и кнопками TTS.
- Объяснение согласования с is/are.
- Блок типичных ошибок.
- Интерактивное задание для закрепления.

## 7. Технические требования

- Использовать текущий Angular и существующую архитектуру проекта.
- Предпочитать standalone-компоненты и современные возможности Angular, совместимые с установленной версией.
- TypeScript strict typing.
- По возможности использовать OnPush и Signals для локального состояния.
- Не добавлять тяжёлые зависимости без необходимости.
- Не использовать небезопасное отображение HTML или отключение санитизации ради Markdown.
- Обеспечить доступность: клавиатура, aria-label, контрастность, управление воспроизведением.
- Обеспечить адаптивность для desktop, tablet и mobile.
- Сохранить существующий механизм прохождения уроков и практических заданий.
- Добавить тесты для новых компонентов, отображения Markdown и работы TTS.

## 8. Порядок реализации

1. Проанализируй существующий код и опиши найденные проблемы.
2. Предложи оптимальную архитектуру блоков теории.
3. Реализуй переиспользуемые UI-компоненты.
4. Интегрируй Piper TTS.
5. Переделай существующий пример Demonstrative Pronouns.
6. Проверь старые уроки на совместимость.
7. Запусти доступные проверки проекта и исправь обнаруженные проблемы.

## Критерии готовности

- Теория больше не отображается одной строкой.
- Markdown корректно разбивается на заголовки, абзацы, таблицы и списки.
- Учебный материал визуально структурирован.
- Примеры поддерживают перевод и TTS.
- Новые уроки можно создавать без изменения Angular-компонентов.
- Существующие уроки продолжают работать.
- Интерфейс удобен на мобильных устройствах.

Итоговая цель: создать масштабируемую систему интерактивной теории, пригодную для английского, испанского и каталонского языков, а не просто исправить форматирование одного урока.

## 3. Ещё одна важная рекомендация

Я бы разделил две проблемы:

Первая — техническая. Сейчас Markdown, вероятно, отображается некорректно, либо весь контент сохраняется как строка без нужных переносов. Это можно исправить относительно небольшими изменениями.

Вторая — методическая. Даже если Markdown отображается правильно, таблицы с четырьмя словами недостаточно для полноценного изучения грамматики.

Поэтому наиболее удачная архитектура — структурированные JSON-блоки + универсальный Angular Theory Renderer.

JSON Lesson Content

Теория, примеры, переводы, изображения, задания

Angular Theory Renderer

Определяет тип блока и выбирает компонент

Grammar cards

Examples + TTS

Tables

Visuals

Mini quizzes

Tips & errors

Так ты сможешь в будущем создавать сотни уроков на разных языках, меняя только JSON, не трогая код компонентов.

И самое главное: я бы предусмотрел в каждом уроке два уровня объяснения — «Кратко» (основное правило за 30 секунд) и «Подробно» (теория с визуальными примерами, исключениями и типичными ошибками). Это особенно удобно, когда пользователь возвращается к уже изученной теме.
